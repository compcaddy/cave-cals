# “Where did you hear about Cave Cals?” and discount codes

Added October 6, 2026. The backend is live; the app side ships with 1.0.5. Creators and the trainer get a code (SARAH) and a page at **CaveCals.com/Sarah**. People who use a code see the code prices on every Cave Cals+ paywall. The owner sees aggregate counts per code; there are no creator payouts, commissions, or creator dashboards.

## In the app

- **The question.** After setup saves, before the post-onboarding offer, `DiscoverySourceView` (`App/DiscountCodes.swift`) asks **Where did you hear about Cave Cals?** with one choice: Trainer or coach, Social media (TikTok, Instagram, YouTube), Friend or family, App Store, Google search, AI (ChatGPT, Claude…), Other (optional text, up to 60 characters). **Continue** needs an answer or an applied code; **Skip** is always there. Cave Cals+ loads behind it; members go straight to Home after it.
- **The code box.** Trainer or coach and Social media open a **Discount code** box under the row; the other answers show a **Have a code?** link that opens it below the list. Type the code (or paste it from the field's own menu; there's no Paste button since October 7, 2026), then **Apply**, which shows a spinner while checking; a red × clears the box. A code that works drops confetti and reads “Code SARAH worked! / Special discount on Cave Cals+”. Capitals, spaces, and punctuation don’t matter. A typed code that wasn’t applied is applied by **Continue**; if it doesn’t work, the question stays. The question is required (no Skip since October 7, 2026); **Other** needs nothing typed.
- **A code that works** shows **Code work! SARAH applied.**, the deal (“Half price on Cave Cals+”), and once RevenueCat has loaded, each plan’s price against the regular one (“$29.99 a year instead of $59.99”). **Remove** clears it.
- **It lasts for good.** The code is kept in the Keychain (`discount.code.v1`), so a reinstall keeps it. Every paywall then shows the code’s RevenueCat offering (`AISubscriptions.offering`), with “Code SARAH applied · Half price on Cave Cals+” under it. Without a code, paywalls (except the one right after setup, which just asked) show **Have a code?**, which opens `DiscountCodeSheet`.
- **Checking.** `POST /api/v1/discount/check` with `{ code }`, unsigned like food search (codes are public, and setup runs before device verification). The answer is `{ code, name, offering, deal }`; unknown and paused codes are a 404 `code_not_found`.
- **Usage stats** (anonymous, opt-out): `onboarding.source` {source: trainer/social/friend/appStore/google/ai/other, other} (`skipped` only from builds before October 7, 2026), `discount.code` {result: applied/notFound/error, code (applied only), from: setup/paywall}, and `code` on `paywall.shown`/`paywall.result`. Codes that don’t work aren’t sent. Check failures are reported under the `discountCode` error area.
- **Testing.** The question is hidden with `--uitesting` and `--screenshots` unless a DEBUG UI test adds `--discovery-question`; UI tests accept `CAVETEST` without the backend and keep codes in memory, as do unit tests. Developer settings → Preview onboarding ends with the question, checks codes without counting them, and saves or records nothing.

## On the website and backend

- **Code pages.** `backend/src/app/[code]/page.tsx` serves CaveCals.com/<code> in any capitalization: who sent it, the deal, the code with **Copy**, and **Copies SARAH, then Get Cave Cals**, which copies the code during the tap and goes through `/<code>/app-store`. That route counts the tap and redirects to `https://apps.apple.com/app/apple-store/id6809208501?pt=<APP_STORE_PROVIDER_TOKEN>&ct=<campaign>&mt=8` (the plain App Store listing without a provider token). Unknown or paused codes redirect home; paths that can’t be codes (favicon.ico) are a 404. Pages are `noindex` and set no cookies.
- **Counts.** `discount_code_daily` keeps per-code totals by Pacific day: page visits (link previews and crawlers skipped), App Store taps, and successful code checks. No IPs, cookies, or device identifiers; code checks use a daily IP hash only for rate limits (60 an hour per address, `DISCOUNT_CHECK_DAILY_LIMIT` a day overall, 20,000 by default), in their own buckets.
- **Admin.** `/admin/codes` (same password as `/admin`): add a code (name, code, campaign token defaulting to the code in lower case, RevenueCat offering defaulting to `discount`), edit, pause or resume, copy its link; per code: page visits, App Store taps, and Applied (7 days · 30 days · all time), plus iPhones that applied it and purchases or trials started with it (from usage stats). Below: how people answered “Where did you hear about Cave Cals?” and the latest Other answers. Codes are 2 to 30 letters or digits; the site’s own page names (admin, privacy, terms, test, api, …) are refused. A code can’t be renamed; add a new one.
- **Apple’s numbers** per campaign token (product page views, first-time downloads, sales) are in App Store Connect → Analytics → Acquisition → Campaigns. Apple counts only people who share analytics with developers and hides small numbers, so expect fewer than the page counts.
- Schema: migration `drizzle/0004_discount_codes.sql` (two new tables; nothing existing changes). Code: `backend/src/server/discount-codes.ts`, tests in `backend-tests/discount-codes.test.ts`.

| With a code | $4.99, 3-day free trial | $29.99, 7-day free trial |

On October 6, 2026 the live prices were $5.99/month and $29.99/year. The current products (`com.philstarkovich.cavecals.ai.monthly` and `.ai.yearly`) become the regular prices; two new products in the same subscription group carry the code prices. Code prices renew at the code price. One subscription group means one subscription per person and one free trial per person across all four products; someone who already had a trial gets the code price without a second one.
