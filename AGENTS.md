# Cave Cals project guidance

## Scope and architecture

- Native SwiftUI / SwiftData app, iOS 17+, project and scheme `CaveCals`, bundle `com.philstarkovich.cavecals`. ECC2 is an alias of this repository.
- iPhone is the target device family. Verify core functionality on iPad in iPhone compatibility mode too, especially subscriptions.
- Backend instructions are in `backend/AGENTS.md`; read them before backend work. Preserve local-first manual logging and server-verified paid AI access.
- Read `README.md` for architecture and `Documentation/Release/Readiness.md` for dated release evidence. Never confuse local changes with an uploaded TestFlight build.

## Current UI decisions (September 16, 2026)

- One home screen, not a diary underneath a suggestions/search sheet. Date and totals stay at the top; the center switches among **Logged** with the hand-drawn checkmark, **Quick Add** with the hand-drawn lightning bolt, and **Meals** with the hand-drawn covered-dish icon. Do not use emoji in this toggle or add a duplicate Suggestions heading.
- Quick Add is the default on initial launch, with the keyboard closed. Brief background/foreground transitions preserve the selected list, query, and date; reset to today's Quick Add after at least 30 minutes in the background. Explicit logging shortcuts still open their requested action. Day rollover remains supported.
- A single search field stays directly above the four footer actions: quick calories, voice, barcode, meal scan. When Quick Calories is expanded, its choices appear above the search field so the search remains anchored at the bottom. No separate Search button or floating Close button.
- Typing replaces the center list with existing manual/numeric add, common-food, local-history, saved-meal, and online results. Hide the list toggle during a nonempty search. Clearing/canceling restores the previously selected list. A successful search-result add clears the query, dismisses the keyboard, switches to Logged, and scrolls to the newest row.
- Search uses only the red in-field X to clear text and dismiss the keyboard (also available when focused with empty text); no separate Cancel button. Hide the Results heading for numeric calorie input.
- Editors, camera, voice, settings, and calendar can still use sheets. Canceling an editor returns to the home screen without creating a search sheet.
- Logged names/calories use 18-point adaptive Schoolbell text with primary color at 0.92 opacity; narrow time-to-description spacing and compact rows. Header spacing is deliberately tight. Tapping a logged row edits it, swiping exposes a red Delete action, and long-pressing opens an Edit/Delete context menu. Keep swipe-to-delete red for meal rows too; do not let the blue app accent tint destructive actions.
- The large consumed-calorie total at the upper left uses the custom Cave Count display font. Keep that font limited to this focal number; goals, remaining calories, labels, and lists continue using Schoolbell.
- Goal progress fills a tall rounded container behind the calorie totals, using pale blue/orange/red so the numbers remain prominent; do not add a separate thin bar. Goal progress is blue through 80% and fills the final 20% in orange. Above goal the bar stays full: preserve the 20% orange warning band and replace blue from the right with red equal to the over-goal percentage (for example, 120% total is 60% blue, 20% orange, 20% red). Cap red at 80% so the orange band remains visible.
- Quick Add rows use a 52-point minimum height with zero vertical list insets. Preserve at least 44-point controls and allow text to grow for accessibility.
- Quick Add ranking is local and deterministic and shows up to ten foods. Blend recent and established habits, smooth food-specific time windows, conditional day patterns, recent meal-session companions, and learned same-day cadence. Strongly suppress an already-logged food only when its history indicates it is normally logged once daily; repeat foods recover according to their typical daily count and gap. Preserve replay metrics and avoid random exploration. User-pinned foods occupy the first Quick Add positions in pin order and count toward the ten-item limit; remaining positions retain algorithmic order.
- Long-pressing a Quick Add row shows **Edit**, **Add**, and **Pin** (or **Un-Pin**). Pinned rows show a pin icon immediately before the food name. The pencil/Edit flow opens Add Calories with a separate **Pin on Quick Add** toggle below the serving/time section, and saving applies the final toggle state even if the food name changed.
- The Meals home list replaces the former Settings → Meals screen. It shows meal name, calorie total, pencil, and blue add circle without repeating the Meals icon on every row. Separate the compact centered **New Meal** button from the first meal with a top border. Long-press offers **Edit**, **Delete**, and **Pin/Un-Pin**; pinned meals stay first and show a pin icon. New Meal opens a taller chooser that shows all five starting points: today’s entries, meal scan, voice log, link/website import, and manual meal items. This chooser uses the fixed red bottom **Cancel** treatment instead of a navigation-bar Cancel. Photo, voice, and link results seed the normal New Meal editor for review before saving.
- Add feedback rotates forward through 360 degrees: blue plus front, plain unboxed checkmark on a transparent reverse, then blue plus again. Honor Reduce Motion and prevent duplicate adds during confirmation.
- Suggestion additions are the exception to the Logged transition: keep Quick Add visible and play the confirmation animation so several suggestions can be logged quickly. Successful Quick Calories, photo, voice, and barcode additions switch to Logged and reveal the newest row at the bottom.
- The barcode sheet is titled **Scan a Barcode**, uses **Cancel** as its navigation action, and does not offer a manual-calorie link. A successful lookup replaces the scanner directly with the populated **Add Calories** editor; never stack that editor over the scanner.
- Selecting a quick-calorie amount focuses the optional name field and opens the keyboard.
- Meal capture pauses the preview connection immediately while retaining the photo capture session; photo settings prioritize speed. Validate actual shutter/preview behavior on hardware.
- Voice Log, Meal Scan (including Review Scan), and the barcode scanner use a fixed, centered red-text **Cancel** action above the bottom safe area. Keep at least a 44-point tap target and do not put Cancel in the top-left navigation bar on these capture surfaces.
- Voice recording uses a blue microphone pulsing opacity, not red/blue color animation. The primary button is blue before recording and turns red while its action is **Stop and Analyze**. Use only the fixed bottom Cancel and omit any additional Cancel inside the card. Processing says “Analyzing your meal…”; interrupted/retryable recordings say “Recording saved” with an explicit next step. Never imply analysis is running when it is not.
- Photo/voice estimate review is titled **Review Scan** and uses the same white-name, calorie, pencil, and blue add-circle rows as Quick Add. Do not show an instructional Foods heading. A single result has no bottom action and dismisses after its row is added. Multiple results show **Add All** below the list; individually added rows keep a persistent checkmark and show the standard “item added” Undo banner. Undo removes that entry and restores its row’s plus button. Add All adds only the remaining rows before dismissing. No top-right Add action. Scan details use a centered blue **view scan details** disclosure below Add All (or below the list for one item), with no background on the disclosure itself; expanding it slides a separate filled details panel into view below.
- AI photo and voice results separate a useful human-scale serving size from the number eaten. Naturally countable food uses one item as the serving size (two bananas becomes `1 banana` × `2`); bulk food uses a familiar household, label, volume, or weight unit. Never use microscopic units such as individual rice grains. When no useful base unit is clear, keep the complete portion as one serving. Preserve compatibility with older cached AI results.
- Toolbar food confirmation actions (Add, Add Meal, and the editor’s Save Changes) use solid blue prominent buttons with white text and a checkmark. Preserve validation/disabled states.
- Keep the supplied launch artwork centered on its matching cream background and the supplied drumstick scan app icon. Do not regenerate artwork without a request.
- The initial setup headline reads on three lines: **You Eat. / App Track. / Weight Drop.**

## Verification and release discipline

- Preserve existing uncommitted user changes. Use focused diffs, build checks, and relevant behavioral tests; cosmetic-only changes do not need new tests.
- Useful simulator test cases in `UITests/ECCUITests.swift`: unified search/list restoration, search-add transition/Undo, and brief background tab preservation. Logging shortcut tests are in `UITests/LoggingActionUITests.swift`.
- A simulator build does not validate physical camera, App Attest, CloudKit production sync, or sandbox subscriptions. State those limits accurately.
- For simulator builds: `xcodebuild -project CaveCals.xcodeproj -scheme CaveCals -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build`.
- For device tests, discover current simulator/device IDs instead of hardcoding historical IDs. Keep app/widget version and build numbers consistent in release archives.
- Build 1.0.1 (2) is the last verified TestFlight upload from this task; later UI changes need a new build/upload when requested. Verify Apple processing and internal group membership before claiming a build is available.
- Do not publish an App Store release, alter storefront availability, or claim the review rejection is resolved merely because a TestFlight upload succeeded.
